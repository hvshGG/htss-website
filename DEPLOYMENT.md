# Публикация HTSS & CO.

Основной адрес: **https://htss-co.kz/**. Текущая рабочая статическая форма использует FormSubmit и отправляет обращения на **info@htss-co.kz**. Этот же способ сохранён в новой версии; для него SMTP и Node.js на хостинге не нужны.

Для замены уже работающего сайта следуйте [MIGRATION.md](MIGRATION.md).

## Готовый пакет для GitHub Pages

Из корня проекта с Node.js 24 или новее:

```sh
npm ci
npm test
npm run package
```

Команда создаёт:

- `dist/` — только публичные файлы сайта;
- `release/htss-co-kz-ready.zip` — содержимое `dist`, уже с `index.html` в корне архива;
- `sitemap.xml`, `robots.txt`, `CNAME`, `.nojekyll` — включены в `dist` и архив.

Загрузите **всё содержимое `dist` или распакованного архива** в текущую папку публикации GitHub Pages. Замены одного `index.html` недостаточно: новая версия использует папку `assets` и `site-config.js`. Не загружайте `.env`, `node_modules`, исходники сервера и тесты.

`CNAME` содержит `htss-co.kz`. Если публикация выполняется из ветки, сохраните его в корне выбранной папки публикации. При существующем custom GitHub Actions workflow сохраните текущую схему deployment и укажите `dist` как источник публичных файлов. DNS и подключённый домен менять не требуется.

На GitHub Pages при необходимости включите **Settings → Pages → Enforce HTTPS**. Проверка HTTP перед подготовкой показала доступность страницы по HTTP без обязательного перенаправления. Не добавляйте `.htaccess`: GitHub Pages не использует настройки Apache.

## Форма заявок

Статический `site-config.js` уже настроен на `delivery: 'formsubmit'`, получатель `info@htss-co.kz`. Адрес endpoint кодирует email как часть URL; `info%40htss-co.kz` означает тот же `info@htss-co.kz`.

В новой форме сохранены имя, телефон и направление; также передаются описание задачи, язык и согласие. Поля письма подписаны по-русски. Сайт проверяет телефон, обязательные поля и согласие; блокирует повторное нажатие во время отправки. Успех показывается только после HTTP-успеха и явного подтверждения FormSubmit. Ошибки, включая ответ `success: "false"`, сохраняют введённый текст.

После загрузки отправьте **одну реальную заявку вручную** и проверьте почту и папку «Спам». Если FormSubmit запросит подтверждение адреса или нового источника формы, подтвердите его из ящика `info@htss-co.kz`. Автоматические проверки используют подменённые ответы; реальные письма не отправляются и активацию почтового ящика не подтверждают.

Запрос FormSubmit отправляется как обычные поля формы (`application/x-www-form-urlencoded`), без предварительного OPTIONS-запроса и без принудительного отключения CAPTCHA. Время ожидания ответа — 45 секунд; автоматических повторов нет, чтобы не дублировать заявки. Если сервис сообщает, что нужна активация, форма показывает отдельное сообщение и сохраняет ввод. Истечение времени ожидания не доказывает, что письмо не отправлено: сначала проверьте почту. Проверка интерфейса без реальных писем: `npm run test:browser -- --contact-only` после сборки.

FormSubmit — сторонний сервис, которому передаются данные формы. Это описано на `privacy.html`. Работа прямой статической отправки зависит от доступности этого сервиса. [Официальная документация AJAX](https://formsubmit.co/ajax-documentation).

## Sitemap и метаданные

Сборка автоматически создаёт согласованные canonical, Open Graph, Twitter image, `robots.txt`, `sitemap.xml` и `CNAME` для `https://htss-co.kz/`.

В sitemap два адреса:

- `https://htss-co.kz/`
- `https://htss-co.kz/privacy.html`

Разделы `#about`, `#services` и переключатели языков не являются отдельными страницами. Старый адрес `#hero-scroller` сохранён как ссылка на начало страницы. `lastmod` не придуман автоматически при каждой сборке.

Если домен когда-нибудь изменится, задайте `SITE_URL` в окружении или `.env` перед сборкой и обновите исходный `CNAME`, sitemap и метаданные. `SITE_URL` принимает только корневой HTTPS URL, без пути, query, fragment и данных авторизации. Для текущей публикации всё уже заполнено.

После замены откройте `https://htss-co.kz/sitemap.xml` и `https://htss-co.kz/robots.txt`. При наличии доступа к Google Search Console отправьте URL sitemap. Это помогает обнаружению страниц, но не гарантирует индексацию. [Google: sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

## Локальный просмотр

Скопируйте `.env.example` в `.env`, если локальной конфигурации ещё нет, затем:

```sh
npm run dev
```

Откройте `http://localhost:3000`. По умолчанию `.env.example` выбирает FormSubmit; локальный сервер разрешает только этот конкретный внешний сервис в CSP. Не нажимайте отправку с тестовыми данными без намерения отправить письмо. Браузерные тесты перехватывают запросы и дополнительно блокируют DNS FormSubmit.

## Необязательный режим Node.js и SMTP

Этот вариант нужен только для собственного обработчика почты вместо FormSubmit. GitHub Pages сам Node.js не запускает.

В `.env` или панели Node-хостинга укажите:

| Переменная | Значение |
| --- | --- |
| `CONTACT_PROVIDER` | `auto` для SMTP или `formsubmit` для существующего внешнего сервиса. |
| `CONTACT_TO` | `info@htss-co.kz` — получатель обращений. |
| `CONTACT_FROM` | Подтверждённый адрес отправителя почтового провайдера. |
| `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS` | Реквизиты почтового провайдера. |
| `SMTP_PORT`, `SMTP_SECURE` | `587` и `false` для STARTTLS либо `465` и `true` для TLS. |
| `PUBLIC_ORIGIN` | Публичный origin, например `https://htss-co.kz`, для проверки запросов. Локально оставьте пустым. |
| `SITE_URL` | `https://htss-co.kz/` для сборки метаданных. |
| `PORT`, `HOST` | По умолчанию `3000`, `127.0.0.1`; в контейнере может понадобиться `HOST=0.0.0.0`. |

После заполнения конфигурации:

```sh
npm run build
npm start
```

Сервер раздаёт `dist`, если в нём есть `index.html`; `npm run dev` всегда использует исходники. Для явного выбора папки есть `PUBLIC_DIR`. При полном SMTP обработчик `POST /api/contact` проверяет ввод, согласие, origin, размер JSON и лимит попыток. Успех означает приём письма SMTP-сервером для нужного адресата, а не гарантию попадания во входящие.

Для `CONTACT_PROVIDER=auto` без полных SMTP-настроек и при наличии email предлагается почтовый черновик; без получателя приём отключён. При явном `CONTACT_PROVIDER=formsubmit` SMTP не используется, даже если его реквизиты заполнены.

Ограничение SMTP-формы — пять попыток за десять минут на IP, в памяти процесса. За одним доверенным reverse proxy, который перезаписывает `X-Forwarded-For`, можно задать `TRUST_PROXY=true`; прямой доступ к Node тогда закрывают. Для нескольких процессов нужен общий лимитер на уровне хостинга. Эти ограничения Node не заменяют защиту внешнего FormSubmit.

Секреты хранятся только в окружении/`.env`. Сервер не раздаёт `.env`, `.git`, серверный код и тесты. HTTPS и запуск процесса на Node-хостинге настраиваются средствами выбранной платформы.
