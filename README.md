# HTSS & CO.

Адаптивный сайт компании для **https://htss-co.kz/**. HTML, CSS и JavaScript; локальные шрифты, изображения и видео. Русская, казахская и английская версии переключаются на странице.

Текущий способ приёма заявок сохранён из работающего сайта: **FormSubmit → info@htss-co.kz**. Для статической публикации SMTP и Node.js на хостинге не нужны.

## Готовый пакет

Нужен Node.js 24 или новее на компьютере для проверки и сборки:

```sh
npm ci
npm test
npm run package
```

Публичные файлы: `dist/`. Архив для замены: `release/htss-co-kz-ready.zip`. В архиве `index.html` находится в корне, рядом с `assets`, `CNAME`, `.nojekyll`, `robots.txt` и `sitemap.xml`.

- [MIGRATION.md](MIGRATION.md) — как заменить существующий сайт, сохранив домен и настройки публикации.
- [DEPLOYMENT.md](DEPLOYMENT.md) — FormSubmit, sitemap/SEO, локальный просмотр и необязательный Node/SMTP.

Заменять нужно все публичные файлы, а не только `index.html`. Ничего автоматически на хостинг не публикуется.

Логотип в шапке и подвале — `assets/media/logo.webp`, облегчённая прозрачная копия предоставленного `logo-web.svg`. Исходный SVG сохранён в проекте; для публикации используется WebP, чтобы не загружать его многомегабайтные встроенные изображения.

## Разработка

Нужен установленный [Node.js 24 LTS или новее](https://nodejs.org/en/download) вместе с npm. После установки полностью перезапустите терминал и VS Code, чтобы обновился `PATH`.

```sh
npm run dev
```

В Windows PowerShell, если запуск блокируется с ошибкой `npm.ps1` / «выполнение сценариев отключено», используйте CMD-версию npm:

```powershell
npm.cmd run dev
```

Если `node` или `npm` «не распознаётся», проверьте установку Node.js и перезапуск терминала. Версии можно проверить командами `node --version` и `npm.cmd --version`.

Откройте `http://localhost:3000`. Для первоначальной настройки Node скопируйте `.env.example` в `.env`. Статика использует `site-config.js`; Node формирует клиентскую конфигурацию из окружения. Не помещайте пароли SMTP в публичные файлы.

## Проверки

`npm test` проверяет сервер, валидацию, sitemap, canonical URL, старые ссылки и согласованность данных публикации.

После сборки `npm run test:browser` проверяет в Chrome/Chromium вёрстку от телефона до большого экрана, три языка, клавиатуру, меню, форму и ошибки ответа FormSubmit. Запросы внешнего сервиса подменяются, а DNS FormSubmit в тестовом браузере заблокирован: реальные письма не отправляются. При необходимости задайте путь к браузеру в `CHROME_PATH`. Скриншоты: `.cache/browser`.

После размещения нужна одна настоящая проверка доставки на целевой email вручную. Она не заменяется автоматическими тестами интерфейса.
