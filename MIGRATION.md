# Замена сайта htss-co.kz

Подготовленный архив: [release/htss-co-kz-ready.zip](release/htss-co-kz-ready.zip). Он предназначен для замены публичных файлов сайта на **https://htss-co.kz/**. Подготовка архива не публикует сайт; реальные заявки при проверках не отправлялись.

## 1. Сохраните текущую публикацию

Сделайте резервную копию всех текущих публичных файлов, включая скрытые файлы, `CNAME`, иконки и файлы подтверждения Google/Яндекс или других сервисов. Сохраните текущие настройки **Settings → Pages**. Для сравнения был предоставлен `index.html`, поэтому состав всех файлов на хостинге неизвестен: существующие файлы подтверждения и иконки не удаляйте.

## 2. Замените файлы в существующем источнике Pages

В **Settings → Pages → Build and deployment** посмотрите, откуда уже публикуется сайт.

- Если используется **Deploy from a branch**, оставьте текущие ветку и папку публикации: корень `/` либо `/docs` согласно настройкам. Распакуйте архив и поместите всё его содержимое именно в эту папку. Вместо архива можно взять всё содержимое `dist/`. `index.html` должен оказаться непосредственно в папке публикации, без дополнительного уровня `dist/` или папки архива.
- Если используется **GitHub Actions**, сохраните действующий workflow и путь Pages-артефакта. Новые публичные файлы должны попасть в папку, из которой этот workflow создаёт артефакт. Не переключайте способ публикации без необходимости.

Не меняйте DNS и репозиторий только ради замены оформления. В подготовленном наборе сохраните `CNAME` со строкой `htss-co.kz` и `.nojekyll`. При публикации из ветки они нужны в её публикуемой папке. При публикации через Actions домен задаётся в настройках Pages; игнорирование `CNAME` этим способом нормально.

Загружайте только публичное содержимое архива или `dist/`. Не загружайте `.env`, `node_modules`, тесты, сервер Node.js и исходный каталог `.git`.

## 3. Проверьте домен и HTTPS

После завершения публикации проверьте, что в **Settings → Pages → Custom domain** остаётся `htss-co.kz`. Включите **Enforce HTTPS**, когда сертификат доступен. Откройте `http://htss-co.kz/` и убедитесь, что браузер переходит на `https://htss-co.kz/`.

В новой вкладке или после обновления без кеша проверьте новый дизайн, меню, языки и форму на телефоне. Один ответ HTTP 200 не подтверждает, что посетители уже видят новую версию.

## 4. Проверьте приём заявки

Статическая версия сохраняет отправку через FormSubmit на `info@htss-co.kz`; SMTP для этого не нужен. Адрес с `%40` в endpoint обозначает тот же символ `@`. Форма проверяет поля и показывает успех только после подтверждения сервиса; это не гарантия попадания письма во «Входящие».

После публикации вручную отправьте одну настоящую тестовую заявку со своими контактами и проверьте получение письма, включая папку «Спам». Если FormSubmit попросит активировать получателя, выполните подтверждение из письма сервиса и повторите проверку. Мы реальных писем не отправляли. SMTP остаётся отдельным вариантом для размещения с сервером Node.js; на GitHub Pages сервер Node.js не запускается.

## 5. Проверьте индексацию

Откройте [sitemap.xml](https://htss-co.kz/sitemap.xml) и [robots.txt](https://htss-co.kz/robots.txt). В карте должны быть два адреса, совпадающие с canonical страниц:

- `https://htss-co.kz/`
- `https://htss-co.kz/privacy.html`

В `robots.txt` должна быть строка `Sitemap: https://htss-co.kz/sitemap.xml`. Языки переключаются на одной странице; отдельные `/ru`, `/kk` и `/en` в карту добавлять не нужно.

В Google Search Console выберите ресурс `htss-co.kz`, откройте раздел **Файлы Sitemap** и отправьте `https://htss-co.kz/sitemap.xml`. Сохраните существующее подтверждение владения ресурсом. Отправка карты не гарантирует немедленную индексацию.

Официальные инструкции: [источник публикации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [свой домен](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site), [HTTPS](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https), [FormSubmit AJAX](https://formsubmit.co/ajax-documentation), [отправка sitemap в Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).
